## 一、项目目标与实现思路

平台面向 Java、Python 程序设计课程，形成“课程组织—教师布置编程作业—学生在线编写和提交—自动判题—AI 辅助复盘”的教学闭环，并提供基于课程资料的知识问答。系统按单台云服务器 **2 核 vCPU、4 GiB 内存**规划，以 Docker Compose 部署。

实现按依赖顺序分阶段推进：先完成账号、角色与教学组织；再实现题目、作业、代码提交和判题；随后接入受控 AI 辅助；当前执行管理界面、用量审计、备份恢复和上线保障。任务书另要求架构图、数据流图、流程图、截图、代码示例和接口说明，这些是课题文档/论文交付物，独立于 M4 软件功能。当前主技术路线为 Vue 3 + Nginx、Java 21 / Spring Boot `app`、Python 3.12 / FastAPI `ai`、PostgreSQL，以及 Redis、RocketMQ、MinIO。实际数据结构以 `deploy/db/V1__init.sql` 至 `V4__m4_admin_ai_review.sql` 为准。

## 四、实施重点与边界

1. **代码执行安全**：当前判题在 `app` 容器内以低权限 `judge` 用户运行子进程，并设置 CPU/进程/文件等限制、运行超时、输出截断和工作目录清理。它没有容器或 namespace 隔离，不能视为强安全沙箱；当前方案仅适用于受控的校内实名场景。若需对公网开放不可信代码执行，必须另行设计隔离执行环境并重新评估服务器资源与架构。
2. **AI 内容复核**：模型输出受到提示词、结构化响应、代码长度限制和判题事实约束；AI 结果不能替代判题结论。教师评价、纠正并由学生回看的流程已写入 PRD §15.8，代码实现列入 M4。
3. **学习时长统计**：任务书提到学习时长；当前核心需求已有提交和 AI 使用等过程记录，但尚无学习时长计算口径。建议先确定“活跃计时、会话超时和统计范围”，再补充 PRD 与实现，避免以页面停留时间冒充实际学习时长。
4. **隐私和密钥**：继续按角色和教学班限制数据访问；生产密钥保存在服务器 `.env`，不写入文档、日志或版本库。论文截图和示例需脱敏。
5. **2C4G 资源约束**：M4 先复用现有服务和 PostgreSQL 查询；新增组件或改变部署拓扑前，先评估常驻内存、磁盘与运维成本并更新 PRD。
