# 部署手册（M1–M4）

面向：阿里云 ECS **2 核 4 GB**（Ubuntu 22.04 / 24.04），Docker Compose 单机。
覆盖范围：M1（账号/组织）+ M2（题库/作业/提交/判题/图片）+ **M3（AI 答疑/思路/分析 + 课程知识问答）**。

---

## 1. 前置条件

| 项 | 要求 | 检查命令 |
|-|-|-|
| 系统 | Linux x86_64，4 GB 内存，≥ 40 GB 磁盘 | `free -h` `df -h /` |
| Docker | 24+，且 `docker compose` 插件可用 | `docker --version` `docker compose version` |
| 端口 | 80（或 `WEB_PORT`）、22 开放；**5432/6379/9876/10911/9000/9001 不对外** | 安全组只放 80/22 |
| 内存余量 | 全栈按 PRD §7.3 约 3.4 GB，需留 ≥ 600 MB | `docker stats` 观察 |

> 2C4G 上**不要**加装额外服务（尤其别在宿主机再跑一套 MySQL/Redis）。

## 2. 首次部署（约 5 分钟）

```bash
# 1) 取代码
cd /opt && git clone <仓库地址> codelab && cd codelab

# 2) 配置环境变量（只提交过 .env.example，.env 不入库）
cp .env.example .env
openssl rand -base64 48            # 生成 APP_JWT_SECRET
vi .env                            # 必改：POSTGRES_PASSWORD / MINIO_ROOT_PASSWORD / APP_JWT_SECRET / APP_ADMIN_PASSWORD

# 3) 一键构建 + 启动（脚本会先体检密钥，再 build + up + 等健康检查）
chmod +x scripts/deploy.sh
./scripts/deploy.sh
```

`deploy.sh` 做的事：docker 可用性 → `.env` 体检（JWT ≥ 32 字符、密码不是示例值）→ `compose build` → `compose up -d` → 轮询 `codelab-app` 的 `/healthz`（最长 120 s）→ 打印访问地址。

打开 `http://<服务器IP>/` 即为登录页；管理员账号 = `.env` 里的 `APP_ADMIN_EMAIL` / `APP_ADMIN_PASSWORD`（启动时幂等创建，已存在则跳过）。

### 2.1 启动顺序（脚本已处理，手工排查时要知道）

```
postgres → （app 等它 healthy 才启动）→ app → web
redis / rocketmq-namesrv → rocketmq-broker / minio  （M1 尚未被代码使用，允许后起）
```

手工全量重启顺序（故障恢复也用这个）：

```bash
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d postgres redis
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d rocketmq-namesrv minio
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d rocketmq-broker
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d app web
```

### 2.2 数据库迁移怎么跑

**不需要手工执行**：`app` 启动时按文件名升序执行 `deploy/db/*.sql`，已执行版本记在 `schema_migrations` 表里并跳过。
脚本本身也是幂等写法（`CREATE TABLE IF NOT EXISTS`），用 `psql -f` 反复跑同样不报错。

加新脚本：放 `deploy/db/V2__xxx.sql`（容器内挂载在 `/app/db`，无需重建镜像），重启 app 即生效。

## 3. 验收（M1 六条）

### 3.1 一条命令跑完

```bash
./scripts/m1-acceptance.sh http://127.0.0.1:8080
# 依赖 curl + python3；要求数据库干净（首次部署后立刻跑），否则会因 409 提前失败
```

### 3.2 手工点验 + 对应 curl

前置：先登录拿 token（下文 `$T` 指 access token，`$A` 指管理员 token）。

```bash
# 管理员登录
curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.edu","password":"<APP_ADMIN_PASSWORD>"}'
```

| # | 验收点 | 怎么做 |
|-|-|-|
| 1 | 建"2028级应用数学2班 × Java程序设计 × 张老师" | `POST /api/admin/school-classes` → `POST /api/admin/courses` → `POST /api/admin/users`(role=teacher) → `POST /api/admin/teaching-classes`（班级/课程/教师/学期） |
| 2 | 导入 5 个学生入班 | `POST /api/admin/users/import`，`Content-Type: text/csv`，正文 `email,display_name,role,class_name` 每行一个学生；响应里 `created=5`，并给出每人的初始密码 |
| 3 | 学生登录 → 我的课程显示 Java 程序设计（张老师） | 浏览器用它登录，或 `GET /api/student/courses` |
| 4 | 教师只看自己的教学班 | 用张老师登录 → `GET /api/teacher/teaching-classes` 只返回 1 条；换王老师登录看不到张老师那条 |
| 5 | 学生把 URL 里的 id 换成别的教学班 → 403/404 | `GET /api/student/courses/<别人的教学班id>` → **404**（不泄露存在性）；`GET /api/admin/users` → 403 |
| 6 | 干净机器 `docker compose up -d` + `./scripts/deploy.sh` → 3 分钟内可登录 | 首次部署时间主要花在拉镜像；`deploy.sh` 自带健康检查等待 |

教师端"非本人教学班"用 id 试探同样是 **404**（`GET /api/teacher/teaching-classes/<别人的id>`）。

## 4. 日常运维

```bash
# 状态 / 资源
docker compose -f deploy/docker-compose.prod.yml --env-file .env ps
docker stats --no-stream

# 日志（app 同时写容器标准输出与 /app/logs/app.log，按天滚动，保留 14 天）
docker logs -f --tail=200 codelab-app
tail -f deploy/logs/app.log

# 只重启后端
docker compose -f deploy/docker-compose.prod.yml --env-file .env restart app

# 发版（无 CI，手动拉 + 重建）
git pull && ./scripts/deploy.sh

# 停止 / 销毁（销毁会删数据卷，慎重）
docker compose -f deploy/docker-compose.prod.yml --env-file .env stop
docker compose -f deploy/docker-compose.prod.yml --env-file .env down            # 保留卷
docker compose -f deploy/docker-compose.prod.yml --env-file .env down -v         # 连卷一起删
```

### 4.1 每日备份 / 恢复（M4）

```bash
# 手工备份：pg_dump 压缩后上传到 MinIO 的 backups/，并清理 7 天前对象
bash scripts/backup.sh

# 查看 MinIO：控制台进入 codelab bucket 的 backups/ 前缀

# 恢复必须使用新数据库名，不会覆盖 POSTGRES_DB 指向的生产库
bash scripts/restore.sh backups/codelab-20261102T010203Z.sql.gz codelab_restore_20261102

# 验证临时库可读
docker exec codelab-pg psql -U codelab -d codelab_restore_20261102 -c '\\dt'
```

`backup.sh` 从仓库根目录 `.env` 读取 PostgreSQL/MinIO 配置；备份文件使用宿主机临时目录，上传成功后自动清理。MinIO 访问地址默认为宿主机 `127.0.0.1:${MINIO_API_PORT}`；若服务不在本机，可在 `.env` 配 `MINIO_BACKUP_ENDPOINT`。脚本只打印对象键与结果，不打印凭证。

每天自动运行：在服务器 crontab 安装以下任务（将 `/opt/codelab` 换成仓库绝对路径）：

```cron
0 2 * * * cd /opt/codelab && /bin/bash scripts/backup.sh >> /var/log/codelab-backup.log 2>&1
```

恢复脚本只允许创建新库；如果恢复失败，新建的临时数据库会保留供诊断，确认后再手工删除。禁止用 `down -v` 做演练。

### 4.2 回滚

镜像不是按版本号打的，回滚靠代码：`git checkout <上一个提交> && ./scripts/deploy.sh`。
数据库脚本只增不改；回滚代码不会回滚已执行的结构变更（新表/新列留在库里，老代码不认识也无害）。

## 5. 常见错误速查

| 现象 | 原因 | 处理 |
|-|-|-|
| `deploy.sh` 报 `APP_JWT_SECRET 至少 32 字符` | 密钥太短 | `openssl rand -base64 48` 写进 `.env` |
| 启动即退出，日志 `Port 8080 was already in use` | 宿主机上有别的进程占 8080 | `ss -lntp \| grep 8080`，杀掉或改 `.env` 的 `APP_PORT` |
| `迁移脚本执行失败: V1__init.sql -> ...` | SQL 语法/权限问题（注意 PG 注释必须是 `--`，不是 `#`） | 按报错行号改脚本；已回滚，不会留半张表 |
| 登录成功但刷新页面就掉线 | 浏览器没存 refresh cookie（HTTP 下用了 `Secure`，或跨站） | `.env` 保持 `APP_COOKIE_SECURE=false`（纯 HTTP 部署必须如此）；确认是同源访问（走 Nginx，不要前后端不同端口） |
| 登录接口返回 `403 Invalid CORS request` | `.env` 的 `APP_CORS_ORIGINS` 未包含浏览器实际来源 | 加入页面 origin（协议+主机+端口），再执行 `docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d --force-recreate app`；不用重启 Docker Desktop |
| 登录返回 423 | 连续 5 次密码错，账号锁 10 分钟 | 等 10 分钟，或用管理员重置密码 |
| 返回 404 而不是 403 | 设计如此：越权资源按"不存在"处理，不泄露存在性 | 检查是否登录了正确账号 |
| 导入 CSV 整批失败 | 表头没写或列顺序不对 | 首行 `email,display_name,role,class_name`；班级名必须**已存在**且完全一致 |
| 容器被 OOM kill | 内存超账本 | `docker stats` 看谁超标；RocketMQ 可先降到 `-Xmx256m`（PRD §7.3 允许） |
| 前端 404 / 白屏 | Nginx 没回退到 index.html | 确认挂载的是 `deploy/nginx/default.conf`（`try_files $uri $uri/ /index.html`） |
| 中文日志乱码 | 容器时区/编码 | `TZ=Asia/Shanghai` 已在 compose 与 Dockerfile 固定 |

## 6. 安全须知（M1 阶段）

1. **当前是纯 HTTP**（Q5 默认不备案）。`api/auth/*` 的 refresh cookie 因此是 `Secure=false`——一旦上 HTTPS，把 `.env` 的 `APP_COOKIE_SECURE=true` 打开。
2. `5432 / 6379 / 9876 / 10911 / 9000` **不要**对公网开放，安全组只放 80（和 22）。
3. `.env` 权限 `chmod 600`，不要提交；轮换密钥后所有人需重新登录。
4. 首个管理员由 `.env` 的 `APP_ADMIN_EMAIL` 创建；**上线后立刻改掉默认密码**。
5. M2 起判题会在宿主/容器内执行学生代码：必须建独立低权限用户 `judge`（PRD §7.4），当前尚未涉及。
6. 审计表 `audit_logs` 只追加，登录成功/失败、管理员建改、名单导入都会落库；排查问题先查它。

## 7. M2 增补：判题与图片（新增必读）

### 7.1 运行镜像变了

`app` 的运行镜像从 JRE 换成 **`eclipse-temurin:21-jdk`**，并装了 `python3`、`util-linux`(runuser)：

| 原因 | 说明 |
|-|-|
| 需要 `javac` | 判题要在容器内编译学生 Java 代码（PRD §7.4） |
| 需要 `python3` | Python 题目判题 |
| 需要 `runuser` | 让学生代码以**低权限用户 `judge`**（uid 2000、无 shell、无 sudo）执行 |

判题工作目录是卷 `appjudge`（容器内 `/data/judge`），每次提交一个子目录，**保留 24 小时后由后台任务删除**。

### 7.2 首次部署后必须做的两项实测

M2 有两处代码在开发机环境无法验证（本机无 Docker/MinIO），**上线后请按下面两条各跑一次**：

```bash
# ① 图片链路（MinIO + 手写 SigV4 签名）
#    用教师账号登录拿 token，再上传一张 png：
TOKEN=...   # POST /api/auth/login 拿到的 accessToken
PROBLEM_ID=...  # 任意一道你建的题的 id
curl -sS -X POST http://<服务器IP>/api/teacher/files \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@/tmp/test.png" -F "problemId=$PROBLEM_ID"
# 期望：201 且返回 {"id":...,"url":"/api/files/..."}；
# 再用浏览器打开该 url（带登录态）应能看到图片。
# 若返回 500 且日志里有 "MinIO 上传失败 status=403" → 检查 MINIO_ROOT_USER/PASSWORD 是否与 .env 一致。

# ② 判题链路（judge 用户 + ulimit）
#    用教师账号建一道 1+1 的题、发布、布置作业；再用学生账号提交正确的 Java 代码：
#    GET /api/student/submissions/{id} 期待 status=done、result=accepted。
# 若 result 一直是 judge_error：
docker logs codelab-app | grep -i judge | tail -50
# 常见原因：judge 用户不存在 / /data/judge 权限 / 镜像里没有 javac 或 python3
docker exec codelab-app id judge
docker exec codelab-app ls -ld /data/judge
docker exec codelab-app which javac python3 runuser
```

### 7.3 判题相关环境变量

| 变量 | 默认 | 说明 |
|-|-|-|
| `APP_JUDGE_ENABLED` | `true` | 关掉后提交会一直停在 `queued` |
| `APP_JUDGE_DIR` | `/data/judge` | 判题工作目录（compose 已给卷） |
| `APP_JUDGE_CONCURRENCY` | `2` | 同时判几个（PRD §6.4 默认 2；2C4G 别调大） |

| `APP_JUDGE_RETENTION_HOURS` | `24` | 判题目录保留时长 |
| `APP_ASSIGNMENT_ALLOW_LATE` | `false` | 截止后是否仍允许提交 |

|-|-|-|
| 服务器 | `minio`（compose 已硬编码） | 图片落 MinIO，桶名 `MINIO_BUCKET`（默认 `codelab`），启动时自动建桶 |

### 7.5 M2 新增验收（对应 PRD §11 M2）

| # | 验收点 | 怎么做 |
|-|-|-|
| 1 | 教师布置 2 题 | 题库建题 → 编用例 → 发布 → 作业里选题 → 发布 |
| 2 | 学生做对 1 题、做错 1 题 | 学生账号在做题页写码提交；`accepted` 与 `wrong_answer` 各一条 |
| 3 | 结果页信息完整 | 通过用例数/总数、首个失败用例的输入/期望/实际、编译错误原文、隐藏用例只显示"第 N 组未通过" |
| 4 | 队列与并发 | 同时提交 3 条，前端能看到"排在第 N 位"；并发上限 2 |
| 5 | 教师进度 | 作业详情里应交/已提交/通过人数、通过率（人）、通过提交数÷总提交数 与提交列表对得上 |
| 6 | 重判 | 教师点"重判"生成新提交记录，旧记录仍在 |

### 7.6 M2 已知边界（写在这里免得以后误判为 bug）

1. **判题不是沙箱**：学生代码能读该用户可读的文件、能发网络请求（PRD §7.4 已明示风险）。上线前必须确认：只对校内实名用户开放；`judge` 用户除 `/data/judge` 外无可写目录；`ulimit -u 64 -f 2048` 生效。
2. **判题队列当前走 PG 表**（`judge_queue`），不是 RocketMQ（PRD §14.1 D1）。RocketMQ 仍在 compose 里但判题没用它，等有 broker 可实测时再切 `JudgeTaskQueue` 的实现。
3. **同一题 10 秒内重复提交会被判为同一次提交**（幂等，FR-SUB-01）。学生想立刻重试，请等 10 秒。
4. **已发布的题不能改题面/用例**，只能「另存为新版本」（FR-PRB-04）。

## 8. M3 增补：`ai` 服务（AI 答疑与知识问答）

### 8.1 多了一个容器，但不对外暴露

| 项 | 值 |
|-|-|
| 服务 | `ai`（Python 3.12 + FastAPI + LangChain LCEL） |
| 端口 | **只 `expose 8080`，不映射宿主机**；只有 `app` 能通过容器网络访问（PRD §15.1 D6） |
| 内存 | `mem_limit 300m`，单 worker、不加载 embedding 模型（PRD §7.3） |
| 鉴权 | app → ai 带 `X-Internal-Token`（`.env` 的 `AI_INTERNAL_TOKEN`，生产必须替换） |
| 健康 | `docker exec codelab-ai python -c "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8080/healthz')"` |

### 8.1.1 上线前的"假 AI"硬检查（M3 补充）

`AI_PROVIDER=stub` 时 AI 回答是**模板话**且不报错，最容易悄悄上线。现在有两道闸：

1. `./scripts/deploy.sh` 会**直接失败**并提示，除非你显式写 `ALLOW_STUB_AI=1 ./scripts/deploy.sh`（只用于演示）；
   同时还会检查 `AI_INTERNAL_TOKEN` 是否仍是示例值、`DASHSCOPE_API_KEY` 是否为空。
2. `app` 启动时会问一次 ai 服务的 `/healthz`，若是 stub 会在日志里打一段醒目 WARN：
   `docker logs codelab-app | grep "假 AI"`。

### 8.1.2 镜像来源说明（MinIO）

MinIO 社区镜像已从 Docker Hub 下架，官方当前分发在 `quay.io/minio/minio`。
compose 里写成 `image: ${MINIO_IMAGE:-quay.io/minio/minio:latest}`，所以：

- quay.io 能拉通就什么都不用改；
- 拉不动（匿名拉取受限/网络原因）就换一个来源，例如 `MINIO_IMAGE=cgr.dev/chainguard/minio:latest`，
  或干脆指向任何一个 S3 兼容服务（改 `MINIO_ENDPOINT` 即可）。
- **首次部署后建议把实际镜像 id 记到运维记录里**（`docker image inspect ... --format '{{.Id}}'`），避免"latest 漂移"。

### 8.2 两种 provider：生产 openai，本地 stub

| `AI_PROVIDER` | 适用 | 说明 |
|-|-|-|
| `openai` | **生产** | DashScope 兼容端点 + `DASHSCOPE_API_KEY`；模型默认 `qwen-plus` |
| `stub` | 仅开发/演示 | 确定性假回答，字段与真实模型一致。**它不产生任何外部调用**，用来在没有 Key 时跑通链路 |

上线前把 `.env` 改成：

```bash
AI_PROVIDER=openai
DASHSCOPE_API_KEY=sk-xxxx
AI_MODEL=qwen-plus
AI_INTERNAL_TOKEN=$(openssl rand -base64 32)
```

`app` 侧另有 `AI_BASE_URL=http://ai:8080`（compose 已写死）与 `APP_AI_CACHE_TTL_MINUTES=30`。

### 8.3 部署后必须实测的两条

```bash
# ① 链路通不通（用教师账号建一条知识条目，学生端问一句）
curl -s http://<服务器IP>/api/student/courses/<courseId>/ai/ask   -H "Authorization: Bearer <student-token>" -H 'Content-Type: application/json'   -d '{"question":"equals 和 == 有什么区别"}'
# 期望：JSON 里 segments 非空；citations 有 entryId（说明检索命中了知识条目）

# ② 真实模型有没有真的被调用（只看 ai 容器日志）
docker logs --tail=50 codelab-ai | grep "task="
# 期望看到 task=chat provider=openai elapsed=... （provider=stub 说明还在假模式）
```

### 8.4 计费与配额的查看口径

| 想看什么 | SQL |
|-|-|
| 今日各任务用量 | `SELECT task, sum(calls), sum(prompt_tokens+completion_tokens) FROM ai_usage WHERE date=current_date GROUP BY task;` |
| 某学生今日 tokens | `SELECT user_id, sum(prompt_tokens+completion_tokens) FROM ai_usage WHERE date=current_date GROUP BY user_id ORDER BY 2 DESC;` |
| 单题调用次数 | `SELECT count(*) FROM ai_calls WHERE user_id=? AND problem_id=? AND charged;` |
| 调低某学生配额 | `INSERT INTO ai_quotas(scope,scope_id,daily_tokens,per_problem_calls) VALUES('student',?,20000,8) ON CONFLICT (scope,scope_id) DO UPDATE SET daily_tokens=excluded.daily_tokens, per_problem_calls=excluded.per_problem_calls;` |

默认值：日 30,000 tokens、单题 10 次（PRD §5.3）。解析顺序 student → 教学班 → global → 默认。

### 8.5 常见问题

| 现象 | 原因 / 处理 |
|-|-|
| 所有 AI 接口 403 `AI_GATE_CLOSED` | **正常**：学生对该题还没有任何提交（时间闸门，PRD §8.2） |
| 思路 L2/L3 打不开（409 `AI_HINT_LOCKED`） | 必须逐级解锁；已通过的题思路整体关闭 |
| 429 `AI_QUOTA_EXCEEDED` | 单题 10 次或当日 30000 tokens 用尽；改 `ai_quotas` 或次日再试 |
| 502 `AI_UNAVAILABLE` | ai 容器挂了 / 超时 / Key 无效。`docker logs codelab-ai` 看 `AI_OPENAI` 报错；先确认 `provider=openai` 且 Key 有效 |
| ai 日志 `provider=stub` | `.env` 里 `AI_PROVIDER` 还是 stub |
| 同一个问题两次问，回答完全一样且很快 | 命中 30 分钟结果缓存（`cached=true`）；每个提交每个任务只允许强制刷新 1 次 |
| 学生能看到完整答案代码吗 | 不能：`key_snippet` 服务端硬截 5 行、`outline` ≤12 行，前端 AI 区域禁止选中/复制，代码片段用 Canvas 绘制 |

### 9.1 已知坑（真机验证时踩到并已修）

| 现象 | 根因 | 处理 |
|-|-|-|
| 图片上传 500，日志 `MinIO 建桶返回 400` | 建桶/上传请求用了 `BodyPublishers.noBody()`，空 body 不带 `Content-Length: 0`，部分 S3 实现直接 400 | 统一用 `ofByteArray(空数组)`；上传遇到 404 会自建桶重试一次 |
| 超时被判成"运行错误"（容器内） | `ulimit -t` 与外层 `waitFor` 同为 2 s，内核 SIGXCPU 抢先 | `ulimit -t` 留 +2 s，并把退出码 152/137/124 归为超时 |
| 判题目录属主是 root，`judge` 用户写不进去 | 具名卷挂到 `/data/judge` 后属主变 root | 容器入口脚本启动时 `chown -R judge:judge /data/judge` |
| `docker compose build` 前端失败 `ERR_PNPM_IGNORED_BUILDS` | corepack 默认拉最新 pnpm（12.x）且拦截依赖安装脚本 | `web/package.json` 固定 `packageManager: pnpm@10.32.1` + `pnpm.onlyBuiltDependencies: [esbuild]` |
