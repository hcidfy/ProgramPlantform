# 操作手册（管理员 / 教师 / 学生）

本手册说明**日常怎么用**这套平台。部署、备份、排障见 `docs/ops/部署手册.md`；接口与规则依据见 PRD v0.2.14（§13~§15 为落地契约，分阶段计划见 §11）。
适用版本：M1（账号/组织）+ M2（题库/作业/做题/判题）+ M3（AI 答疑 / 思路提示 / 正确结果分析 / 课程知识问答）；M4 管理、配额、审计和备份页面/脚本在本地验收中；AI 回答评价与教师复核尚未开放。

登录入口：`http://<服务器IP>/`。账号由管理员创建（学生/教师**不能**自助注册成教师；学生页面可自助注册，注册后需管理员分班）。

---

## 0. 一次完整的教学闭环长什么样

```
管理员：建行政班 → 建课程 → 建教师账号 → 建教学班（班级×课程×教师×学期）→ 导入学生入班
   ↓
教师：建题（题面/用例/图片）→ 发布题 → 建作业（选题+分值+截止）→ 发布作业（一键推给全班）
   ↓
学生：登录 → 我的作业 → 做题（在线编辑器）→ 提交 → 看判题结果（错在哪一组）→ 改代码再交
   ↓
教师：作业详情看进度（应交/已交/通过/通过率）→ 逐个看学生代码 → 必要时重判
```

## 1. 管理员

### 1.1 首次登录

`APP_ADMIN_EMAIL` / `APP_ADMIN_PASSWORD`（在服务器 `.env` 里）即首个管理员，应用启动时自动创建。
**上线后请尽快改掉默认密码**（当前无改密页面，需管理员在数据库侧处理或联系开发者）。

### 1.2 建立教学组织（顺序不能乱）

| 步骤 | 做什么 | 为什么 |
|-|-|-|
| ① 建教师账号 | 角色选 `teacher`，给初始密码 | 教师不能自助注册 |
| ② 建行政班 | 选择启用教师作为班主任，并可导入学生名单 | 行政班代表学校真实班级；学生和班主任在此维护 |
| ③ 建课程 | 例：`JAVA101 / Java程序设计` | 题目挂在课程下；同一门课的教师共享题库 |
| ④ 建教学班 | 选 班级 + 课程 + 任课教师 + 学期（例 `2026A`） | 绑定班级和课程；`(班级,课程,学期)` 不可重复 |

「组织管理」下分为「班级 / 教师账号 / 课程 / 教学班」四个子页面。班级页面可查看名单、添加已有学生、移出学生或导入 CSV；选择班级后，CSV 学生行的 `class_name` 留空会自动使用当前班级。填写了班级名仍要求完全匹配。教师账号可停用/启用以保留历史；关联教学数据的班级、课程和教学班不能删除。

### 1.3 批量导入学生（CSV）

`POST /api/admin/users/import`，`Content-Type: text/csv`，列固定为：

```csv
email,display_name,role,class_name,password
liyi@example.edu,李一,student,2028级应用数学2班,Stu@20261
lier@example.edu,李二,student,2028级应用数学2班
```

- 首行表头可写可不写（以 `email` 开头就会被当表头跳过）。
- `role` 省略= `student`；`password` 省略= 系统生成 11 位初始密码。
- 响应里 `createdUsers[].initialPassword` 就是**要发给学生的初始密码**，请抄下来；`failed[]` 会给出失败行号与原因。
- `class_name` 必须与已存在的行政班**完全一致**，否则该行失败。
- 教师也能用这个接口导入（`role=teacher`，此时 `class_name` 留空）。

### 1.4 日常维护

| 需求 | 接口 |
|-|-|
| 查账号 | `GET /api/admin/users?role=student&q=李` |
| 建单个账号 | `POST /api/admin/users` |
| 退班（学生回到未分班） | `DELETE /api/admin/enrollments/{studentId}` |
| 停用教师账号 | 教师账号页点「停用」；保留教学历史。需要恢复时点「启用」 |
| 删班级/课程/教学班 | 对应 `DELETE`；有学生、作业或关联教学班时会拒绝（409），保留教学历史 |

### 1.5 AI 配额和用量看板

顶部「AI 配额与用量」中，“今日用量”是平台所有用户当天实际完成并入账的 AI 调用总和，日期按数据库 `current_date` 切换；“本月”从本月 1 日累计到今天。登录、打开页面和命中缓存不会产生 token；模型调用完成后才记输入/输出 token。当前模型响应不会因为日额度中途截断，可能完成后使累计值超过额度，之后的新调用会被拒绝。开发配置 `AI_PROVIDER=stub` 时，token 按字符长度估算，只用于本地流程检查，不是真实模型 token 或费用；接入真实 provider 后按 provider 返回的 usage 记录。

每日 token 上限是每个学生的提示词输入与回答输出总和，30,000 是每日总额而非单次回答长度。当前默认单次输出上限为 1,000 tokens，因此额度通常可支持多轮短问答；课程上下文、代码和题目内容也会计入输入，实际轮数会少于 30 次。单题次数只约束做题页的错误解释、思路提示、结果分析；课程问答只受每日 token 上限约束。专项配额优先顺序是学生 > 教学班 > 全局默认。费用按 `.env` 配置的当前模型输入/输出单价估算，不能替代服务商账单。“今日按任务聚合”是按功能统计；“本月按课程聚合”是按本月课程上下文汇总；“已配置的专项配额”列出显式覆盖默认值的学生或教学班。

## 2. 教师

### 2.1 我的教学班

登录后默认页是「我的教学班」，列出你任课的班（别人的教学班你看不到，浏览器里换 id 试探会得到"不存在"）。
点开可以看到该班学生名单。

### 2.2 建题（题库 → 新建题目）

| 字段 | 说明 |
|-|-|
| 标题 | 学生看到的名字 |
| 语言 | Java 或 Python 3（决定判题方式与初始代码模板） |
| 难度 / 时间限制 / 内存限制 | 时间默认 2000 ms；Java 内存由 `-Xmx` 控制，Python 由 `ulimit -v` 控制 |
| 题面 | **Markdown**；可用「上传图片」插入题图，题面里会写成 `![](/api/files/xxx)` |
| 初始代码模板 | 学生打开做题页时编辑器里的初始内容 |

保存后进入题目编辑页：

1. **测试用例**：每行一个用例，填输入/期望输出，勾"隐藏"= 学生看不到内容（判题失败只显示"第 N 组未通过"）。用例最多 20 个。
2. **发布**：发布前至少要有 1 个用例；发布后题目才能被布置进作业。
3. **已发布的题不能改题面和用例**：要改就点「另存为新版本」，会复制出一个 v+1 的草稿，改完再发布。

> 用例的输出比较规则：忽略行尾空格与末尾空行，其余逐字比较。学生程序退出码非 0 记"运行错误"，超时记"超时"。

### 2.3 布置作业（作业 → 新建作业）

1. 选教学班（决定推给哪个班）。
2. 填标题、说明、截止时间。
3. **选题**：只列本课程**已发布**的题；每道题可设分值。
4. 创建后是**草稿**，学生看不到；点「发布」= 一键推送给该教学班全部学生（学生下次打开"我的作业"就能看到，无需选课/接受）。

截止时间之后：学生仍可从作业入口打开题目练习。练习入口不带作业 ID，因此判题提交不会进入作业记录、通过率或分数；未过期时提交才计入作业。需要逾期计分补交时，需先另行设计并验收相应流程。

### 2.4 看进度与提交

作业详情页顶部 5 个数字：

| 数字 | 口径 |
|-|-|
| 应交人数 | 教学班学生总数 |
| 已提交人数 | 至少交过一次的学生数 |
| 通过人数 | 作业里**每道题都有通过记录**的学生数 |
| 通过率(人) | 通过人数 ÷ 应交人数 |
| 通过提交数÷总提交数 | 和 PRD §3.1 一致的那个百分比 |

下面「学生提交」表可以点「看代码」查看该次提交的完整信息（含隐藏用例的期望/实际），点「重判」会**新建一条提交**重新排队，旧记录保留。
> 教师查看学生代码会写入审计日志（`teacher.view_code`）。

### 2.5 维护课程知识库（M3）

入口：顶部导航「知识库」。这是 AI 知识问答**唯一的依据来源**——写得越具体，问答越准。

| 操作 | 说明 |
|-|-|
| 新建条目 | 标题 + 内容（Markdown）+ 标签（逗号分隔）。**创建后是草稿，不进检索池** |
| 发布 | 发布后才参与检索（立刻生效） |
| 编辑 | 草稿和已发布条目都可修改；已发布内容修改会留审计，后续检索使用新内容，历史回答保持不变 |
| 删除 | 只有草稿可删除；已发布条目不可删除 |
| 标签 | 用于检索匹配，建议把学生常用的词写进去（`equals`、`重载`、`ArrayList`） |
| 本班问答记录 | 页面下方按教学班看学生问过什么，用来发现共性疑问（不做社区，没有回复功能） |

检索方式（无向量库）：关键词命中 + `pg_trgm` 相似度 + 标签匹配，取前 5 条拼进模型上下文，并要求模型只在条目范围内作答、标注引用。
**知识量小的时候这条路够用**；条目越少命中越差，所以建议每门课先写 10~20 条高频问题。

### 2.6 复核学生标记的 AI 回答（M4 规划）

M4 将提供「AI 回答复核」队列。教师进入本人任教的教学班，查看学生标记为“没帮助”的 AI 回答、反馈原因和必要上下文，然后选择“回答正确 / 部分正确 / 回答错误 / 无法验证”。部分正确或错误时，填写面向学生的修正；无法验证时说明原因。提交后学生可看到复核结论和修正，AI 原答会保留。

复核页默认不展示学生完整源代码；确有必要时使用现有「看代码」入口，系统会记操作日志。教师只能处理本人教学班范围内的学生和课程。**此功能尚未上线，接口与规则见 PRD §15.8。先在本地 Docker 环境按教师、学生角色完成逐步走查，用户确认前不上传或部署云端。**

## 3. 学生

### 3.1 我的课程 / 我的作业

- 「我的课程」= 本班所有教学班（课程名 + 任课教师 + 学期）。
- 打开课程详情后可按「关闭」收起。“AI 验收”若出现在 M3 验收课程说明中，是验收演示用文字，不表示课程已连接 AI，也不是一个单独的操作功能。
- 「我的作业」= 本班**已发布**的作业，每题后面显示我的状态：未开始 / 已提交未通过 / 已通过。

### 3.2 做题与提交

点「去做题」进入做题页：左上是题面（Markdown，含题图），下面是代码编辑器（Monaco，Java/Python 语法高亮）。

点「提交判题」后：

1. 状态从 **排队中 → 判题中 → 已完成**，队列有积压时显示"排在第 N 位"。
2. 判题结果给出：通过用例数/总数、得分、每个用例的状态与耗时。
3. 有未通过的用例时，会展示**首个未通过用例**的输入/期望/实际（各截断 500 字符）；**隐藏用例只显示"第 N 组未通过"**。
4. 编译错误会显示 `javac`/`python3` 的原文（截断 4 KB）。

### 3.3 会被拦下来的情况

| 情况 | 结果 |
|-|-|
| 代码超过 64 KB | 413，提示代码过大 |
| 同一题 10 秒内连续提交 | 第二次直接返回第一次的结果（幂等），**等 10 秒再交** |
| 判题队列积压 > 20 | 429，提示稍后再试 |
| 作业已截止 | 作业入口转为独立练习，不计入作业提交和分数 |
| 提交别人的题 / 看别人的提交 | 404（不泄露存在性） |

### 3.4 我的提交

按时间倒序列出你的所有提交，点「查看」能看到当时的代码、判题明细与失败用例信息。

## 3.5 学生：和 AI 讨论这道题（M3）

### 3.5.1 什么时候能用（时间闸门，最重要的一条规则）

| 状态 | AI 可用性 |
|-|-|
| **这道题一次都没提交过** | 做题页**不出现任何 AI 入口**；直接调接口返回 403 |
| 提交过（无论对错） | 答疑、三级思路、正确结果分析都可用（受配额） |
| 已通过 | 思路提示关闭（没意义了），仍可问"为什么"、可看正确结果分析 |

理由：AI 是**复盘工具**，不是代写工具。这也是为什么平台完全不需要"AI 内容审核"。

### 3.5.2 三个按钮分别是什么

| 按钮 | 给什么 | 不会给什么 |
|-|-|-|
| **问 AI 为什么错** | 错误定位（行号，能定位时）、原因、下一步怎么做 | 完整代码 |
| **思路 L1 → L2 → L3** | L1 概念 / L2 算法方向 / L3 伪代码骨架，**必须逐级解锁** | 可编译的完整程序 |
| **分析正确结果** | 为什么没通过、首个失败用例的期望与实际、差距、怎么改（checklist） | 完整代码 |

- 同一个问题重复点，30 分钟内会命中缓存（更快、不重复计费）；每题每题任务可以"强制刷新 1 次"。
- **同一题同一个思路等级只计费一次**。
- 配额：单题 **10 次**、每日 **30000 tokens**；用尽会提示 429，当日不恢复。

每日 30000 token 是**每个学生**的输入与输出累计量，不是单次回答长度；单题 10 次仅用于做题页的解释、思路和分析。课程问答只受每日 token 限额。服务端在新调用开始前检查限额；当前模型响应不会因额度在生成中达到上限而被截断，后续请求才会被拒绝。页面加载、登录、缓存命中不会扣 token；只有真实模型调用完成后才按返回用量计入。

**「一次」到底怎么算**（这也是"10 次够不够"的答案）：

| 动作 | 计几次 |
|-|-|
| 点一次「问 AI 为什么错」/「分析正确结果」/ 某个思路等级 | **1 次** |
| 30 分钟内重复点同一个按钮（命中缓存） | **0 次** |
| 同一个思路等级再看一次 | **0 次**（同题同级只计费一次） |
| 点「强制刷新一次」（每个提交每类只允许 1 次） | **1 次** |

所以 10 次大致等于一整轮调试：答疑 3~4 次 + 思路三级各 1 次 + 分析 1 次 + 再追问 2 次。
如果某门课确实需要更多，管理员可以调（见部署手册 §8.4 的 `ai_quotas`，或改
`APP_AI_DEFAULT_PER_PROBLEM_CALLS`）；调整后新调用立即生效。

### 3.5.3 为什么 AI 的回答复制不了

AI 区域禁止选中与右键，关键代码片段是**用 Canvas 画出来的**（页面 DOM 里没有可复制的文本）。
产品定位是"提高抄袭成本"，截图与开发者工具拦不住——UI 上也写明了这一点。

## 3.6 学生：课程知识问答（M3）

入口：顶部导航「课程问答」。

1. 选课程（只列出你所在班级开设的课程）。
2. 直接提问，例如"Java 里 == 和 equals 有什么区别"。
3. 回答是分段的；下面「引用的知识条目」可以展开看原文。
4. 如果没有检索到已发布的课程知识条目，系统提示“课程资料暂未覆盖”，不调用模型也不扣 token。可改用条目中的课程术语提问，或联系教师补充/修改资料。
5. 可以继续追问（同一会话保留最近 5 轮上下文），也可以点「+ 新会话」。

> 这类问答走的是**课程知识库**，不是"问 AI 写作业"，所以不受"首次提交"闸门限制。

## 3.7 学生：评价 AI 回答并查看教师复核（M4 规划）

M4 将在每条答题解疑和课程问答的 AI 回答下提供“有帮助 / 没帮助”评价。选择“有帮助”只记录评价；选择“没帮助”需选择原因（结论错误、内容不完整、表达不清、答非所问、其他），可补充不超过 500 字的说明，并进入任课教师复核队列。

提交后可在“我的 AI 反馈”查看待复核状态。教师完成复核后，学生可查看教师判断与修正说明。修正会作为原 AI 回答的补充保留，原回答不被覆盖，也不会自动变成课程公共知识条目。**以上流程尚未在当前版本上线，PRD 契约见 §15.8。新流程先在本地环境人工验收，用户确认后才进入云端部署。**

## 4. 判题结果怎么读

| 结果 | 含义 | 学生该做什么 |
|-|-|-|
| 通过 (accepted) | 全部用例输出正确 | 完成 |
| 答案错误 (wrong_answer) | 有输出不对的用例 | 看首个失败用例的输入/期望/实际，对着改 |
| 编译错误 (compile_error) | 编译没过 | 按编译原文修语法/类型错误 |
| 运行错误 (runtime_error) | 程序异常退出（退出码非 0） | 检查数组越界、空指针、除零等 |
| 超时 (timeout) | 超过时间限制（题目时限×2 后被杀） | 优化算法复杂度或检查死循环 |
| 判题异常 (judge_error) | 判题机自身出问题（不是学生代码的问题） | 联系老师；老师看服务器日志 |

## 5. 常见问题

| 现象 | 原因 / 处理 |
|-|-|
| 登录成功但刷新就掉线 | 纯 HTTP 部署时 `.env` 必须 `APP_COOKIE_SECURE=false`；且要**同源**访问（走 Nginx，不要前后端各开端口） |
| 学生「我的作业」是空的 | 作业还是草稿（导师没点发布）；或学生没分班（页面会提示联系管理员） |
| 教师「题库」里看不到某门课 | 你没有该课程的教学班；题库按"你任教的课程"过滤 |
